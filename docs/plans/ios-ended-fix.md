# iPhone 跳轉中暫停讓播放器壞掉（小級）

## 狀態
實作中（擁有者 2026-11-10 同意）

## 證據（擁有者貼回的診斷紀錄：iPhone Safari 18.7、iPhone Chrome 157）
- 按下跟讀：`seekSegmentStart(org, 19.90)`（seeking=1）→ 靜音 `play()` → 解鎖 promise 一結束就 `pause()`
- 跳轉中被暫停：`pause → suspend ct=0.00 → seeked ct=0.00 → ended`
- 之後每次設定 19.90，`seeked` 後仍是 `ct=0.00`；就位 6 秒逾時 →「原音載入失敗」
- 已播完（ended）狀態下按播放，WebKit 依規則從頭播 → 解釋了 PR #35 以來「每句都從音檔開頭播」、「第三次才成功」（碰巧跳轉已完成才沒壞）
- 電腦版 Chromium 沒有這個行為，所以先前都測不出來

## 做法
1. 每個播放器只解鎖一次（`unlockedRef`）；解鎖時**原地**靜音播放，不設定起點、不改語速，播起來就暫停（沒有跳轉中的暫停）
2. 解鎖結束（暫停）之後才設定起點；`prepareSegmentStart` 等跳轉完成、位置正確才錄音
3. `prepareSegmentStart` 自動修復：播放器 `ended`，或跳轉完成仍不在起點兩次 → `load()` 重新載入一次（約 2 秒），載入後再跳
4. 診斷紀錄多記 `ended`、`dur`
5. PR #42「按下時先設定起點，再做靜音解鎖播放」驗收測試依擁有者同意改成「解鎖時不跳位置，解鎖結束後才設定起點」

## 驗收條件
- ✅ `tests/iosEndedFix.test.ts`：依紀錄重現的假播放器（跳轉中暫停 → 0 秒＋ended、之後跳轉落在 0）；ended → 重新載入後 ready；跳轉無效兩次 → 重新載入；只重新載入一次；正常情況不重新載入；跟讀只解鎖一次、解鎖不跳位置、解鎖結束後才設定起點、就位後才錄音；診斷紀錄含 ended／dur
- 👀 iPhone 正式版：同一份教材連續跟讀 5 句（含第 1 句、後段句），每次第一次按就從句首播、停在句尾；若異常請貼診斷紀錄
