# 規劃：自動跟讀（連續一句接一句）

- **級別**：中（一般新功能；不改資料結構、不新增套件）
- **PR**：#50
- **狀態**：實作中（擁有者 2026-11-13 核准）

## 目標
在跟讀畫面按「自動跟讀」後，從目前這一句開始：原音＋錄音 → 評分 → 顯示分數 5 秒 → 自動進下一句，一直到使用者按「停止」或教材結束。

## 背景與使用情境（擁有者 2026-11-13）
- 擁有者原話：「例如從第一句按自動播放，便開始一句開始跟讀，一句跟讀完回報分數五秒接著下一句，直到使用者點擊停止鈕」
- 目前每一句都要手動按「開始跟讀」，評分後再按「下一句」→ 長教材（100 句以上）操作很瑣碎
- 主要裝置：iPhone（Chrome／Safari，WebKit），戴耳機

## 現況（對照程式）
- `ShadowingPracticeView`：`idle → recording → buffer → scoring → scored／scoreError`
  - `handleStart`：點擊當下解鎖錄音播放器與原音（每個播放器只解鎖一次，PR #45）→ 麥克風 → 原音就位（`prepareSegmentStart`，6 秒逾時）→ 開始錄音 → 原音播放 → 句尾進入 6 秒緩衝倒數（緩衝中靜音 1.5 秒就提早結束）→ 停止錄音 → `runScoring`
  - `runScoring`：轉文字（Groq→OpenAI，參考原句）→ 計分 → 交易寫入熟練度 → `scored` → **自動播放自己的錄音**
  - 換句（`sentenceIndex` 改變）時 effect 會停止所有播放、中止錄音、重設狀態；元件本身不會重新掛載（`MaterialDetailView` 只改 `practiceIndex`）
  - 頁面隱藏（鎖屏、切 App）：錄音中會直接暫停原音並進入緩衝倒數
- 熟練度規則（內容 ≥ 70 且總分 ≥ 70 才累加）、重逢紀錄完全沿用，不因自動模式改變

## 做法（草案，待委員會評估）
### 1. 狀態與流程
- 自動模式狀態放在 `ShadowingPracticeView` 的 ref＋state（換句不會重新掛載，所以可以延續）；離開跟讀畫面就結束
- 每句：自動呼叫與手動相同的 `handleStart`（不另寫一套）→ 評分 → `scored` → 顯示「5 秒後下一句」倒數 → `onNext()` → 新句子 idle 時自動 `handleStart`
- 第一句由使用者點擊「自動跟讀」開始（iPhone 播放與麥克風解鎖都在這次點擊完成）；之後的句子不需要點擊（播放器已解鎖、麥克風已開）

### 2. 「分數 5 秒」的計時起點（**需要擁有者決定**）
- 目前評分後會自動播放自己的錄音（約與句子等長）
- 方案 A：自動模式**不自動播放錄音**，評分完成立刻倒數 5 秒（建議：節奏最快、不會和下一句原音重疊）
- 方案 B：照常播放錄音，播完才開始倒數 5 秒（每句多出一句的長度）

### 3. 停止與各種中斷
- 「停止」按鈕：任何階段都可按
  - 錄音中按：中止這次錄音、**不評分**
  - 評分中按：讓評分完成並存檔，但不進下一句
  - 倒數中按：停在這一句的結果頁
- 自動結束的情況（都停在目前這一句，並顯示原因）：
  - 最後一句完成：顯示本次摘要
  - 頁面隱藏（鎖屏、切 App）
  - 原音載入失敗（就位逾時）、麥克風錯誤
  - 評分失敗（網路）：顯示錯誤，可按「重試評分」後繼續或停止
  - 使用者手動操作：按返回、跳到別句（桌機列表）、按「再念一次」、按聽聽看
  - **連續 2 句沒有偵測到聲音**（轉文字空白或內容 0 分）：判斷使用者離開，自動停止（避免白白呼叫轉文字、亂寫熟練度）
- 倒數中有「立即下一句」

### 4. 沒通過的句子（**需要擁有者決定**）
- 方案 A：照樣進下一句（建議：符合「一句接一句」；沒過的句子在摘要列出）
- 方案 B：沒通過就同一句再來一次，最多 N 次後才進下一句

### 5. 已精熟（1000）的句子（**需要擁有者決定**）
- 方案 A：一樣練（建議：維持順序，簡單）
- 方案 B：自動略過

### 6. 本次摘要（自動模式結束時）
- 練了幾句、通過幾句、平均總分、熟練度增加的句數；沒通過的句子清單（點了可以跳過去）

### 7. 畫面
- 跟讀主按鈕旁加「自動跟讀」次要按鈕（只在 idle 顯示）
- 自動模式中，畫面上方固定一列：「自動跟讀中・第 N 句」＋「停止」
- 結果頁倒數：「5 秒後下一句」＋「立即下一句」＋「停止」
- 第一次使用顯示耳機提醒（沿用既有提醒）

### 8. iPhone 與長時間使用
- 螢幕自動鎖定會中斷 → 自動模式期間申請 **Screen Wake Lock**（iOS 16.4 以上支援；不支援時提示「請把自動鎖定時間調長」）
- 程式觸發的 `play()`：原音與錄音播放器都已在第一次點擊時解鎖；`AudioContext` 被系統暫停時 `mic.resume()` 可能失敗 → 偵測到就停止自動模式並提示「點一下繼續」
- 診斷紀錄（`playbackTrace`）照常記錄，每句加上「自動」標記

## 第一輪評估後的修正（委員會：Gemini、Nemotron、DeepSeek；Poolside 已下架。Codex 5 項）
### A. 自動流程的狀態契約（Codex 🔴）
- 邏輯集中在新的純函式模組 `src/utils/autoShadowing.ts`（狀態機），元件只負責把事件送進去、執行它回傳的動作 → 競態可以寫成自動測試
- **世代（generation）**：每次開始、停止、手動跳句都遞增；所有計時器與非同步回呼都帶世代，世代不符就不做事
- **專用倒數計時器**（不共用錄音緩衝用的 `timerRef`）
- **每次作答最多前進一次**：結果倒數到期、「立即下一句」、停止三者同時發生時，只有第一個生效
- **換句後才啟動**：`onNext()` 之後，等換句 effect 重設完成、新句子 id 符合「等待自動開始的句子 id」且狀態是 idle，才呼叫 `handleStart`（每句只啟動一次）
- **最後一句不呼叫 `onNext`**（會停在同一句），直接結束並顯示摘要
- 不是自動流程造成的換句（返回、桌機列表跳句、「再念一次」、聽聽看）→ 結束自動模式

### B. 停止與頁面隱藏：逐階段定義（Codex 🔴）
| 階段 | 按停止 | 頁面隱藏（鎖屏、切 App） |
|---|---|---|
| 準備中（等麥克風、原音就位） | 取消這次開始，不錄音 | 同左 |
| 錄音中、緩衝倒數中 | 中止錄音、**不評分**、原音暫停 | 同左（自動模式不沿用手動的「隱藏就進緩衝並評分」） |
| 評分中 | 只結束自動模式；評分照常完成、存檔並顯示結果 | 同左 |
| 結果倒數中 | 清掉倒數，停在這一句的結果 | 同左 |
- 「開始的取消」與「評分結果是否顯示」分開：準備中停止用獨立的 `startToken`，不遞增 `scoringTokenRef`（否則評分中停止會讓結果不顯示）

### C. 麥克風恢復失敗要看得到（Codex 🔴）
- `micSession.resume()` 改回傳是否成功（AudioContext 是 running）；自動模式每句開始前檢查
- `waitLive`（麥克風真的有收到音訊）逾時的結果不再丟掉：自動模式下逾時就中止這次、不評分
- 失敗時停止自動模式，畫面顯示「麥克風暫停了，點一下繼續」：這一下是真的點擊，可以重新解鎖，並從這一句繼續自動跟讀
- 驗收加入：第二句前 AudioContext 被暫停、resume 被拒、麥克風 track 中斷

### D. 「沒有聲音」改用錄音音量判斷（Codex 🟠、Nemotron、DeepSeek）
- 不再用「內容 0 分」判斷（有出聲但念錯也可能 0 分）
- 錄音期間用既有的音量監測，累計「有聲音」的時間；整段錄音有聲音的時間不到 0.3 秒 → 判定沒有聲音
- 沒有聲音的句子：**不送轉文字、不寫分數**（省費用、不寫入錯誤資料），畫面顯示「沒有偵測到聲音」，仍倒數 5 秒進下一句
- 連續 2 句沒有聲音 → 自動停止；任何一句有聲音就歸零
- 手動模式維持原狀

### E. 摘要的結算（Codex 🟠）
- 只計入「自動模式中開始、而且熟練度交易成功」的作答；以作答編號去重，「重試評分」成功只算一次
- 評分中按停止：摘要顯示「評分中…」，等這句評分完成（成功或失敗）才更新
- 按返回離開跟讀畫面：不顯示摘要
- 摘要內容：練了幾句、通過幾句、沒有聲音幾句、平均總分（只算有評分的句子）、熟練度增加幾句、沒通過的句子清單（可點擊跳過去）

### F. 其他補充
- 評分失敗：停止自動模式，結果區顯示「重試評分」與「繼續自動跟讀」
- 耳機提醒：第一次按「自動跟讀」若跳出提醒，由提醒卡上的按鈕在同一次點擊開始自動模式
- 沒有可跟讀的句子（全部刪除）時不顯示「自動跟讀」
- 無障礙：「停止」有 `aria-label`；倒數用 `aria-live="polite"`；摘要用對話框 `role="dialog"`
- 自動模式中，診斷紀錄的每一筆動作加上「自動」與句子編號

## 擁有者決定（2026-11-13）與對應做法
1. **播完自己的錄音才倒數 5 秒**：評分完成後照常自動播放錄音；錄音 `ended`（或播放被擋、或超過錄音長度＋3 秒的保險時間）才開始倒數。播放中可按「立即下一句」或「停止」
2. **沒通過照樣進下一句**，摘要列出
3. **已精熟（1000）的句子自動略過**：開始時若目前這句已精熟，從後面第一個未精熟的句子開始；前進時也略過已精熟與已刪除的句子；後面都沒有就結束（顯示「後面沒有未精熟的句子」）
   - 開始的句子不是目前這句時，播放與麥克風的解鎖仍在這次點擊內完成（把 `handleStart` 開頭的解鎖抽成 `unlockInGesture()`）
4. 緩衝維持 6 秒＋靜音 1.5 秒提早結束
5. 實作細節：麥克風檢查不改 `micSession` 介面——自動模式在取得麥克風後檢查 `ctx.state`，不是 running 就嘗試 `resume()`（最多等 1 秒），仍不行就停止並顯示「點一下繼續」；`waitForMicLive` 回傳 timeout 也視為麥克風失敗

## 驗收條件
1. 按「自動跟讀」後，從目前這一句開始；評分完成後倒數 5 秒自動進下一句並自動開始 ✅
2. 停止：錄音中按不評分；評分中按仍存檔但不前進；倒數中按停在結果頁 ✅
3. 頁面隱藏、返回、跳句、再念一次、聽聽看、原音載入失敗、麥克風錯誤 → 自動模式結束 ✅
4. 評分失敗 → 停止並可重試 ✅
5. 連續 2 句沒有聲音（以錄音音量判斷）→ 自動停止；沒有聲音的句子不送轉文字、不寫分數；有出聲但 0 分不算沒有聲音 ✅
5a. 競態（純函式狀態機測試）：倒數到期同時按停止／立即下一句只前進一次；手動跳句後舊回呼不前進；停止後不會再啟動錄音；評分中停止仍顯示並保存結果 ✅
5b. 麥克風：第二句前 AudioContext 暫停、resume 被拒、track 中斷 → 停止並顯示「點一下繼續」✅
5c. 摘要：只計入交易成功的作答，重試不重複計；評分中停止，摘要等評分完成才更新 ✅
6. 最後一句完成 → 顯示摘要 ✅
7. 熟練度與重逢的規則與手動相同（同一個 `runScoring`）✅
8. 刪除的句子不會被播到（沿用 `onNext` 的略過）✅
9. Wake Lock：開始時申請、結束時釋放；不支援時不影響功能 ✅
10. 👀 iPhone：連續自動跟讀 10 句，每句原音從句首播、停在句尾，分數顯示 5 秒後進下一句；中途鎖屏會停止

## 手動試用步驟
1. iPhone 開一份教材，進入第 1 句跟讀，按「自動跟讀」
2. 連續跟讀 5 句，觀察每句分數停 5 秒後自動進下一句
3. 在錄音中按「停止」→ 不評分；再按「自動跟讀」從這一句繼續
4. 故意兩句不出聲 → 自動停止
5. 跟讀中鎖屏 → 回來時自動模式已停止
6. 選一份短教材跟到最後一句 → 顯示摘要

## 需要擁有者決定的問題

2. 沒通過的句子：照樣下一句（建議）／重來最多 N 次
3. 已精熟的句子：照樣練（建議）／略過
4. 緩衝倒數（原音結束後最多 6 秒）在自動模式是否縮短？（建議維持 6 秒＋靜音 1.5 秒提早結束）
