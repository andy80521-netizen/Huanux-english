# 規劃：自動跟讀（連續一句接一句）

- **級別**：中（一般新功能；不改資料結構、不新增套件）
- **PR**：#50
- **狀態**：規劃中

## 目標
在跟讀畫面按「自動跟讀」後，從目前這一句開始：原音＋錄音 → 評分 → 顯示分數 5 秒 → 自動進下一句，一直到使用者按「停止」或教材結束。

## 背景與使用情境（擁有者 2026-11-13）
- 擁有者原話：「例如從第一句按自動播放，便開始一句開始跟讀，一句跟讀完回報分數五秒接著下一句，直到使用者點擊停止鈕」
- 目前每一句都要手動按「開始跟讀」，評分後再按「下一句」→ 長教材（100 句以上）操作很瑣碎
- 主要裝置：iPhone（Chrome／Safari，WebKit），戴耳機

## 現況（對照程式）
- `ShadowingPracticeView`：`idle → recording → buffer → scoring → scored／scoreError`
  - `handleStart`：點擊當下解鎖錄音播放器與原音（每個播放器只解鎖一次，PR #45）→ 麥克風 → 原音就位（`prepareSegmentStart`，6 秒逾時）→ 開始錄音 → 原音播放 → 句尾進入 6 秒緩衝倒數（緩衝中靜音 1.5 秒就提早結束）→ 停止錄音 → `runScoring`
  - `runScoring`：轉文字（Groq→OpenAI，參考原句）→ 計分 → 交易寫入熟練度 → `scored` → **自動播放自己的錄音**
  - 換句（`sentenceIndex` 改變）時 effect 會停止所有播放、中止錄音、重設狀態；元件本身不會重新掛載（`MaterialDetailView` 只改 `practiceIndex`）
  - 頁面隱藏（鎖屏、切 App）：錄音中會直接暫停原音並進入緩衝倒數
- 熟練度規則（內容 ≥ 70 且總分 ≥ 70 才累加）、重逢紀錄完全沿用，不因自動模式改變

## 做法（草案，待委員會評估）
### 1. 狀態與流程
- 自動模式狀態放在 `ShadowingPracticeView` 的 ref＋state（換句不會重新掛載，所以可以延續）；離開跟讀畫面就結束
- 每句：自動呼叫與手動相同的 `handleStart`（不另寫一套）→ 評分 → `scored` → 顯示「5 秒後下一句」倒數 → `onNext()` → 新句子 idle 時自動 `handleStart`
- 第一句由使用者點擊「自動跟讀」開始（iPhone 播放與麥克風解鎖都在這次點擊完成）；之後的句子不需要點擊（播放器已解鎖、麥克風已開）

### 2. 「分數 5 秒」的計時起點（**需要擁有者決定**）
- 目前評分後會自動播放自己的錄音（約與句子等長）
- 方案 A：自動模式**不自動播放錄音**，評分完成立刻倒數 5 秒（建議：節奏最快、不會和下一句原音重疊）
- 方案 B：照常播放錄音，播完才開始倒數 5 秒（每句多出一句的長度）

### 3. 停止與各種中斷
- 「停止」按鈕：任何階段都可按
  - 錄音中按：中止這次錄音、**不評分**
  - 評分中按：讓評分完成並存檔，但不進下一句
  - 倒數中按：停在這一句的結果頁
- 自動結束的情況（都停在目前這一句，並顯示原因）：
  - 最後一句完成：顯示本次摘要
  - 頁面隱藏（鎖屏、切 App）
  - 原音載入失敗（就位逾時）、麥克風錯誤
  - 評分失敗（網路）：顯示錯誤，可按「重試評分」後繼續或停止
  - 使用者手動操作：按返回、跳到別句（桌機列表）、按「再念一次」、按聽聽看
  - **連續 2 句沒有偵測到聲音**（轉文字空白或內容 0 分）：判斷使用者離開，自動停止（避免白白呼叫轉文字、亂寫熟練度）
- 倒數中有「立即下一句」

### 4. 沒通過的句子（**需要擁有者決定**）
- 方案 A：照樣進下一句（建議：符合「一句接一句」；沒過的句子在摘要列出）
- 方案 B：沒通過就同一句再來一次，最多 N 次後才進下一句

### 5. 已精熟（1000）的句子（**需要擁有者決定**）
- 方案 A：一樣練（建議：維持順序，簡單）
- 方案 B：自動略過

### 6. 本次摘要（自動模式結束時）
- 練了幾句、通過幾句、平均總分、熟練度增加的句數；沒通過的句子清單（點了可以跳過去）

### 7. 畫面
- 跟讀主按鈕旁加「自動跟讀」次要按鈕（只在 idle 顯示）
- 自動模式中，畫面上方固定一列：「自動跟讀中・第 N 句」＋「停止」
- 結果頁倒數：「5 秒後下一句」＋「立即下一句」＋「停止」
- 第一次使用顯示耳機提醒（沿用既有提醒）

### 8. iPhone 與長時間使用
- 螢幕自動鎖定會中斷 → 自動模式期間申請 **Screen Wake Lock**（iOS 16.4 以上支援；不支援時提示「請把自動鎖定時間調長」）
- 程式觸發的 `play()`：原音與錄音播放器都已在第一次點擊時解鎖；`AudioContext` 被系統暫停時 `mic.resume()` 可能失敗 → 偵測到就停止自動模式並提示「點一下繼續」
- 診斷紀錄（`playbackTrace`）照常記錄，每句加上「自動」標記

## 驗收條件
1. 按「自動跟讀」後，從目前這一句開始；評分完成後倒數 5 秒自動進下一句並自動開始 ✅
2. 停止：錄音中按不評分；評分中按仍存檔但不前進；倒數中按停在結果頁 ✅
3. 頁面隱藏、返回、跳句、再念一次、聽聽看、原音載入失敗、麥克風錯誤 → 自動模式結束 ✅
4. 評分失敗 → 停止並可重試 ✅
5. 連續 2 句沒有聲音 → 自動停止 ✅
6. 最後一句完成 → 顯示摘要 ✅
7. 熟練度與重逢的規則與手動相同（同一個 `runScoring`）✅
8. 刪除的句子不會被播到（沿用 `onNext` 的略過）✅
9. Wake Lock：開始時申請、結束時釋放；不支援時不影響功能 ✅
10. 👀 iPhone：連續自動跟讀 10 句，每句原音從句首播、停在句尾，分數顯示 5 秒後進下一句；中途鎖屏會停止

## 手動試用步驟
1. iPhone 開一份教材，進入第 1 句跟讀，按「自動跟讀」
2. 連續跟讀 5 句，觀察每句分數停 5 秒後自動進下一句
3. 在錄音中按「停止」→ 不評分；再按「自動跟讀」從這一句繼續
4. 故意兩句不出聲 → 自動停止
5. 跟讀中鎖屏 → 回來時自動模式已停止
6. 選一份短教材跟到最後一句 → 顯示摘要

## 不要做的事
- 不改評分規則、熟練度規則、重逢規則
- 不另寫一套錄音／播放流程（一律呼叫既有 `handleStart`／`runScoring`）

## 需要擁有者決定的問題
1. 5 秒倒數的起點：自動模式不播自己的錄音（建議）／播完才倒數
2. 沒通過的句子：照樣下一句（建議）／重來最多 N 次
3. 已精熟的句子：照樣練（建議）／略過
4. 緩衝倒數（原音結束後最多 6 秒）在自動模式是否縮短？（建議維持 6 秒＋靜音 1.5 秒提早結束）
