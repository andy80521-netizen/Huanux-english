# 規劃：語言模型練習的出題方式重新設計

- **級別**：大（重要 AI 提示詞；可能新增句子欄位、重新產生既有題目）
- **PR**：#29
- **狀態**：完成（等擁有者試用與 Merge）

## 目標
讓「念出來練習」的題目**真的能引導使用者說出那一句**，並且有效訓練口說：使用者看到題目 → 能在腦中組出原句 → 說出來 → 評分。題目不能讓人「照題目回答卻被判錯」。

## 背景與使用情境（擁有者 2026-10-31 回報）
- 原句（使用者自己造的）：`All that she wrote will be published.`（句型 all that …）
- 題目（問答題）：「如果一本書的所有內容都將被公開發表，你會怎麼說這件事？」
- 結果：內容 0 分、7 個字不一致。使用者照題目情境回答，跟原句完全對不上；題目裡沒有「她」「寫」，主詞變成「一本書」
- 擁有者：題目很難融入情境，要重新檢討出題方式，研究怎樣有效讓使用者應用句子、達到口說進步

## 現況分析（Claude 對照程式碼）
1. **出題提示詞資訊不足**（`netlify/shared/prompts.ts` `buildPracticePromptsPrompt`）：只給英文原句和句型，要求「回答這個問句最自然的答案就是原句」。沒有要求題目保留原句的**所有資訊**（誰、做了什麼、時態、語氣），AI 為了讓問題聽起來自然，會改主詞、省略細節
2. **題型和評分互相矛盾**：評分是「精準背出原句」（`compareWords`，`errors === 0` 才累加），但「回答問題」「情境任務」天生有很多種正確答法（例如 It will all be published）。使用者越認真融入情境，越可能被判錯
3. **語言沒有規定**：提示詞沒說題目用中文還是英文；畫面卻把問答題當英文顯示（`lang="en"`、英文襯線大字）
4. **沒有品質檢查**：產生後直接存進句子（`qaQuestion`、`situationalPrompt`），之後永久重複使用；壞題目只能靠手動「換一組題目」
5. **沒有中文意思**：使用者自己造的句子（`PatternExampleSentence`）沒有存中文翻譯，題目是唯一線索
6. **看圖題同樣有問題**：圖片很難表達「她寫的」「將會出版」這類資訊；熟練度高時看圖題比例最高（45%）
7. 出題模型：`callQualityText`，溫度 0.3

## 學習原理（設計依據，請委員補充或反駁）
- **主動回想（retrieval practice）**：自己想出來比重看一遍記得牢；但前提是**線索足以想出答案**，想不出來的回想沒有效果
- **漸進撤除提示（fading cues）**：一開始給完整線索（中文全意），熟了之後只給部分線索（情境＋關鍵字），最後只給情境
- **輸出假說（output hypothesis）**：被迫說出完整句子，才會發現自己不會的地方
- **遷移（transfer）**：只背固定句，換個情境可能就說不出來；能把句型用在新內容，才是「會用」

## 做法（定案，2026-10-31 擁有者核准）
### 定位
題目是「**回想你自己造過的那一句**」的提示（中翻英式線索），不是開放式回答。完整中文意思**永遠顯示**，因為評分要求一字不差。

### 題目內容（新欄位，`PatternExampleSentence`）
- `cueVersion`：題目版本，新版為 `2`；沒有或小於 2 ＝ 舊題目，**不再使用**
- `situationZh`：一句中文情境（在哪裡、對誰說）
- `meaningZh`：原句的完整中文意思，必須涵蓋主詞、動作、時態／語態、否定、數量、對象，不可換主詞
- `cueVerified`：品質檢查是否通過
- 產生新題目時**移除**舊的 `qaQuestion`、`situationalPrompt`（擁有者決定：舊題目全部一致換成新題目）
- 句型文字用 `pattern.text`（呼叫端傳入，不讓 AI 自己寫）

### 依熟練度顯示（`src/utils/practiceCue.ts`，擁有者 10/31 追加 500 以上英文題目）
| 熟練度 | 顯示 |
|---|---|
| < 400 | 中文情境＋完整中文意思＋句型 |
| 400～499 | 完整中文意思＋句型 |
| 500～699 | **英文題目**：對方說的一句話＋英文改寫的意思（不用原句用字與句型）＋句型 |
| ≥ 700 | 英文題目；句型藏在「看提示」 |
- 英文題目：自動用英文語音依序播放「對方的話 → 英文改寫」，文字預設隱藏，可按「顯示文字」（測聽力，不影響熟練度）
- 英文題目時，中文意思放在「看提示」裡（不影響熟練度）
- 英文改寫太接近原句（錯字數 < max(2, 原句字數 40%)）或直接用了句型 → 不存英文題目，500 以上仍用中文題目
- **單字提示**：所有熟練度都可按「看單字提示」，把原句的單字打亂顯示；**看過之後，這一句這次的作答都不加熟練度**（含「再念一次」），維持複習也視為沒有背出（`isExact = false`）
- **看圖**：有圖片時當作情境插圖，和題目一起顯示；不再有「只看圖」的題目
- 題目朗讀：中文題目念中文意思（中文聲音）；英文題目念英文

### 產生流程（前端 `src/services/practicePrompts.ts` 協調，各自一次 Function 呼叫，避免逾時）
1. `ai-text` 新 task `practiceCue`：回傳 `{ situationZh, meaningZh, partnerLineEn, meaningEn }`（後端檢查型別、截斷 500 字；英文欄位含中文字時丟掉）
2. `ai-text` 新 task `practiceCueCheck`：只給情境、中文意思、句型（**不給原句**），請 AI 說出英文句子
3. 前端用 `compareWords` 比對原句：`errors === 0` → `cueVerified: true`
4. 不通過 → 重新產生一次（共最多 2 輪）；仍不通過 → 照樣存，`cueVerified: false`，畫面小字「這題可能不夠明確，可換一組題目」，**不擋練習**
5. 檢查呼叫失敗 → 存題目、`cueVerified: false`；產生呼叫失敗 → 不寫入，顯示錯誤，可再試一次／跳過
6. 寫入用既有交易，句子內容已變更就放棄
- 舊題目：練到那一句（或按「換一組題目」）時產生新題目並取代；**不做一次全部重刷**（費用、逾時、無備份）
- 造句完成後背景產生改為新流程

### 不改的地方
- 評分（`compareWords`、`canAccumulatePattern`）、熟練度公式、解鎖規則
- 看圖題的圖片產生（`generate-practice-image.ts`）

### 之後另開規劃
- 「應用」練習：換個情境用句型自由說，AI 評估，不計熟練度

## 驗收條件
1. `practiceCue` 提示詞：要求繁體中文、涵蓋所有資訊、不可換主詞、附擁有者案例當反例；`practiceCueCheck` 提示詞不含原句（✅ 提示詞測試）
2. 後端 `practiceCue`／`practiceCueCheck` 輸入檢查與輸出截斷（✅）
3. 產生流程：檢查通過 → verified；第一次不通過、第二次通過 → verified；兩次都不通過 → 仍回傳、unverified；檢查失敗 → unverified；產生失敗 → 拋錯（✅ 純函式，AI 以替身）
4. 依熟練度顯示：0、399、400、699、700、1000 各自顯示的內容正確；≥ 700 一定有中文意思（✅）
5. 舊題目（沒有 `cueVersion` 或 < 2）視為需要重新產生，即使有 `qaQuestion`（✅）
6. 單字提示：包含原句每個單字（去掉標點）、順序和原句不同、空句子不出錯（✅）
7. 看過單字提示：熟練度不累加，維持複習回報 `isExact = false`（✅）
8. 寫入新題目時保留熟練度、排程、圖片、檢查結果等其他欄位，移除舊題目欄位（✅）
9. 練習畫面、題組內容頁不再使用舊題目欄位（✅ 原始碼檢查）
10. 👀 擁有者句子 `All that she wrote will be published.` 產生的中文意思含「她」「寫」「全部」「將會」「出版」
11. 👀 實際練 5～10 句不同句型：看中文意思能說出原句

## 手動試用步驟
1. 用 Email 測試帳號登入預覽網站，進入語言模型 → 任一句型 → 已解鎖的組別練習
2. 確認題目是中文：情境、你想說的中文意思、句型（依熟練度不同）
3. 按「看單字提示」→ 出現打亂的單字；念對後顯示「看過單字提示，這次熟練度不增加」
4. 有圖片的句子：圖片和中文意思一起出現
5. 題組內容頁點開一句：看得到情境與中文意思
