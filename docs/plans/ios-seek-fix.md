# iPhone 長教材播放從開頭開始（小級）

## 狀態
實作完成，等待審查與擁有者試用

## 問題（擁有者 2026-11-09）
- iPhone（Chrome，底層與 Safari 相同）上新匯入的 9 分鐘教材：跟讀、詳情頁播放、聽句尾**每次**都從音檔開頭播
- 9 月 8 號的短教材（幾分鐘內）正常
- 「不管有沒有調整過時間」都一樣

## 已排除
- 音檔：兩份 mp3 都是 CBR 320kbps、Info 檔頭的幀數與位元組數和實際完全吻合、整份解碼無錯誤
- 資料：背景存檔建立的教材格式與舊前端存的相同，時間都是數字（存檔前驗證）
- 程式時序：電腦版 Chromium 以同一音檔、同樣的「靜音解鎖 → 跳到 300 秒 → 正式播放」流程，準確從 300 秒播

## 根本原因（擁有者 2026-11-09 23:24 補充：正式版舊教材也每一句都從頭播）
- PR #35（2026-11-08 21:16 合併）第 3 輪把跟讀／詳情頁／校對的起點設定改成 `seekSegmentStart`：**音檔還沒載入（readyState 0）就不設定，等 loadedmetadata 才設定**
- iPhone 不預先載入音檔，而從教材頁點一句跟讀每次都會建立新的播放器 → 每次都走這條路，而 iPhone 在已要求播放後才收到的起點會被忽略 → 從 0 秒播
- 原本（直接設定 currentTime，沒載入時瀏覽器記成預設起點）用了好幾個月都正常；電腦版會預先載入，所以一直測不出來
- 修正：恢復「一律立刻設定」，loadedmetadata 時再確認一次；`tests/segmentEnd.test.ts` 對應的驗收測試經擁有者同意修改

## 原本的判斷（保留紀錄）
iPhone 跳到「還沒下載的位置」失敗並回到 0 秒（短音檔一下就整份下載完，所以正常）。沙盒測不到 WebKit、也連不到 Firebase Storage，無法直接證實。

## 做法
0. `seekSegmentStart` 恢復一律立刻設定 currentTime（見上方根本原因）
1. `guardSegmentStart`（`src/utils/segmentEnd.ts`）：播放中確認位置；落在起點前 0.5 秒以上 → 再設定一次（最多 2 次）→ 仍不行改用 `網址#t=起點` 重新載入並播放 → 再不行就暫停並顯示診斷文字（目標、目前、長度、可跳轉範圍、已下載範圍、狀態）
2. 接到所有直接跳位置的入口：跟讀錄音、詳情頁播放一句／編輯器試聽、校對畫面播放一句／聽句尾、結果頁聽聽看（RetellView、重逢原本就用 `#t=`）
3. 跟讀按下時先設定起點再做靜音解鎖播放
4. 聽句尾維持句尾後多播 0.5 秒（擁有者：不要拿掉）

## 驗收條件
- ✅ `tests/iosSeekGuard.test.ts`：設定被忽略一次 → 補跳成功；播放後被重設 → 拉回；一直被忽略 → `#t=` 重新載入；`#t=` 也無效 → 暫停並回報；跳轉中／暫停中不判斷；起點 ≤ 0.5 秒不處理；取消後拆監聽；四個入口接線；跟讀先設定起點再解鎖；聽句尾仍多播 0.5 秒
- 👀 iPhone 用這份 9 分鐘新教材，挑後段句子：詳情頁播放、調整時間的播放片段／聽句尾、跟讀、聽聽看，都要從正確位置開始；若出現「沒辦法跳到這一句的開頭」訊息，請截圖（含診斷文字）
