## 做法

### 1. 新增純函式 `src/utils/groupMastery.ts`
`groupMasteryBars(sentences, groupIndex, startMastery?)` → 長度固定 10 的陣列，第 i 格對應 id `p_<組>_<i>`（與 `GroupDetailView` 相同的編號規則）：
- `{ id, created, mastery, gain, mastered }`
- `created`：該句存在且 `checked`；沒造句的格子 `mastery` 0、`gain` 0
- `mastery`：夾在 0～1000；`mastered`：≥1000
- `gain`：有傳 `startMastery[id]` 時為 `max(0, mastery − start)`，沒傳為 0（完成畫面用；只算增加、不顯示減少）
- 其他組的句子、id 不符規則的句子忽略

### 2. 本次增加量（念出來練習）
在 `runScoring` 既有的 `updatePatternSentences` 更新函式裡，把舊熟練度一起放進 `outcome`（**只是多記一個值給畫面用**，不寫進 Firestore）：
- 更新函式每次被呼叫（交易重試）**一開始先把 `outcome` 清成 null**，找不到句子回傳 null 時 outcome 也維持 null（Codex）
- 只有 `updatePatternSentences` 回傳非 null（真的寫入）且 `newMastery − oldMastery > 0` 才顯示金色 +N；+0 不顯示（Codex、Grok）
- 階段上限：有部分增加時 +N 與「已到目前階段練習上限」同時出現；已在上限、增加 0 時只留提示（Grok）
- 不改 `calculateMasteryAfterAttempt`、不改寫入內容、不改一字不差才累加的規則；字不一致時不顯示增加量（沿用現有提示）
- 新增可選回呼 `onMasteryUpdated?(sentenceId, before, after)`：只在上述「真的寫入」時呼叫，給今日複習的完成畫面用（見下）；句型詳情入口不傳，行為不變

### 2b. 完成畫面的資料來源（Codex、DeepSeek、Grok）
- 今日複習在這次練習期間記一份 `sessionResult`：`句子 id → { before, after }`，由 `onMasteryUpdated` 填入；**同一句重念以最後一次為準**
- 10 根長條：起始值＝開始練習時的 `startMasteryMap`（**先把 `patternId::sentenceId` 的鍵轉成句子 id**）；目前值＝`sessionResult.after`，沒有就用最新的 `patterns`；佇列外的句子（已精熟、未到期）沒有起始值 → gain 0，只顯示目前熟練度
- 三個統計（練習句數／熟練度合計／本次精熟）改用同一來源計算，避免慢網路時先顯示 +0、監聽回來才跳動；**計算規則不變**（合計＝目前−起始、精熟＝起始 <1000 且目前＝1000、練習句數＝`completedKeys.size`，含跳過的題目，與現行相同）
- 長條動畫只播一次；資料晚到只更新高度、不重播；減少動態效果時直接顯示終值
- 顏色：底段 accent、這次增加段 gold；開始前就已滿 1000 的整根 gold（不和「金色＝這次增加」衝突，Grok）

### 2c. 共用元件的行為契約（Codex）
`PatternPracticeSessionView` 由今日複習與句型詳情（造句練習）兩個入口共用，改版只搬動按鈕位置，以下接線**完全不變**：
- 結果頁最後一題的「完成練習」與其他題的「下一句」都呼叫 `onNext`（今日複習靠它進入總結與結算維持複習；句型詳情由父層決定下一句或返回）
- 出題失敗時「跳過這題」呼叫 `isLastSentence ? onBack : onNext`，「返回」呼叫 `onBack`
- 每次評分完成都呼叫 `onScored(sentenceId, total, isExact)`（維持複習以最後一次為準）
- 「再念一次」沿用 `handleRetry`（題型可能重抽，為既有行為）

### 3. 動效
- 總分與熟練度增加量沿用 `countUpValue` 跑動（同 ②a 跟讀），減少動態效果時直接顯示
- 完成畫面長條：長高動畫只在第一次出現時；減少動態效果時直接顯示
- 練習中不加任何新動畫（藍圖：練習時克制）

### 3b. 版面細節（委員會）
- 句型、題目、原句、辨識文字一律可換行（`break-words`），不截斷；10 根小長條用彈性寬度，窄卡不溢出
- 念出來練習：雙欄以**容器寬度 ≥ 60rem（960px）**判斷（Grok），1024px 視窗或句型詳情的窄頁面都維持單欄；手機的錄音鈕／結果按鈕區固定在練習畫面捲動區底部，題目很長時也按得到
- 今日複習：組別卡兩欄與右側欄只在夠寬時出現（右側欄 `xl` 以上；1024px 時維持複習放在組別上方）；沒有維持複習時不留空欄
- 「完成練習」不再用綠色，改主按鈕（accent）；「再念一次」次要按鈕
- 看圖題不顯示「播放題目」（沿用現行）；目標原句只在評分後出現（沿用現行）
- 沒造句的格子畫成虛線空格，有造句但熟練度 0 的格子是實心底色，兩者分得出來（Gemini）

### 4. 共用
- 這 3 個元件不再使用 `slate-`、`indigo-`、`red-`、`emerald-`、`amber-`、`green-`、`orange-`、`yellow-`、`purple-` 色階 class
- 不改任何 handler、狀態流轉、Firestore 讀寫、AI 呼叫、評分與熟練度規則、維持複習規則
